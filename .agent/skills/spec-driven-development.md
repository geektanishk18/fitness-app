# Spec-Driven Development

**Purpose:** Convert product requirements into small, verifiable work.

**Use when:** Starting a phase or feature with multiple acceptance conditions.

**Principles:** Clarify scope, define observable acceptance criteria, map files and dependencies, then implement incrementally.

**Workflow:** Read `AGENTS.md` and relevant docs, inspect existing code, write acceptance criteria, create a focused plan, implement one slice, verify it, and update docs.

**Verification:** Each criterion has a test, inspection, or reproducible manual check. Stop at the phase gate.

**Avoid:** Speculative future work, vague “done” definitions, and silently changing locked decisions.
